// Purpose:
//   Map the dedicated SB-v-BB Starting Strategy after an ACTUAL flop X/C while
//   preserving both preflop origins described by the source:
//     A) SB limp -> BB check (limped pot);
//     B) SB raise -> BB call (MNR/SRP pot).
//
// Primary source: `6- CRUSHFEST 3wSBvBB`.
//   * medium/weak draw flop X/C is price/range sensitive;
//   * if that draw IMPROVES on an overcard Turn -> Donk 75-100%;
//   * if it improves on an undercard Turn -> CHECK with X/R intention;
//   * source rationale for 75-100 is to create ~1:1 river SPR and then shove.
//
// Deep-cash migration review:
//   The Turn lead itself and the 75-100 interval are direct source facts (T).
//   The mature DeepCrusher implementation chooses pot at local SPR <=1.80 and
//   otherwise 75%, while also scheduling a River shove. Those are short-stack
//   implementation details, not direct Starting-Strategy thresholds.
//
//   CashCrusher therefore keeps the directly authored LOWER size (75%) at this
//   gate and does NOT persist a River-shove plan. Pot sizing is not globally
//   prohibited: it may be re-enabled in this exact node when later runtime/solver
//   evidence shows the source's ~1:1 target is appropriate for current cash SPR.
//   This is node-by-node review, not blanket removal of short-stack logic.
//
// Evidence boundary:
//   The exact flop draw class and faced price belong Flop defense. Three dedicated
//   defense-owned markers are reserved below. Until one is written by the audited
//   Flop Call-vs-Bet owner, the no-made source branch deliberately fails closed.
//
// Source/Provenance:
//   T = direct 3wSBvBB topology, X/C draw branch, OC-vs-UC action split, 75-100.
//   A = `improve` resolved as current PairOrBetter, matching mature implementation;
//       Gate08A clean-X/C parent repair; deterministic 75% deep-cash size choice.
//   A/P = exact 4-6h SB-v-BB descendants after every earlier seat folds.
//   X = generic inherited <=1.80 -> pot and automatic River-shove implication.
//
// Safety:
//   No Turn jam, no River action, no generic TP/OP lead, no HandPower/random,
//   no `Raise_Committed`, and no strategy is inferred from the scenario label.
// ============================================================================
